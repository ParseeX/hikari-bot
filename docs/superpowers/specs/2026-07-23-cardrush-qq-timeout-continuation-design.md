# Cardrush QQ 发送超时容错设计

## 背景

Cardrush 图报已经能够稳定生成并发送，但 QQ/NapCat 偶尔会在图片实际送达后返回
`ActionFailed(retcode=1200)`。当前手动图报和自动日报都在整批发送循环之外捕获异常，
因此任意一页出现该返回值后，会停止发送剩余页面；手动命令还会向聊天发送“生成失败”。

## 目标

- `retcode=1200` 只表示本页发送结果未知，不再作为整份图报失败。
- 不重试出现 `1200` 的页面，避免图片已经送达时重复发送。
- 继续发送同一份报告的后续页面，以及自动日报的后续管理员。
- 手动命令不向 QQ 聊天弹出 `1200` 错误。
- 自动日报在出现可容忍的 `1200` 后，仍继续执行 B 站发布。
- 其他错误保持原有失败行为，避免掩盖真正的发送故障。

## 方案

在 `cardrush_delivery.py` 增加一个与 NoneBot 解耦的逐页发送函数：

```python
async def send_qq_pages(
    pages: Sequence[bytes],
    send_page: Callable[[str], Awaitable[object]],
    *,
    log_prefix: str,
) -> list[int]:
    ...
```

函数将页面编码成 QQ 使用的 `base64://` URI，再传给调用方提供的实际单页发送回调。
函数按顺序发送页面，并只捕获 OneBot V11 的
`error.info["retcode"] == 1200`；对其他兼容实现则回退读取 `error.retcode`。命中时记录
内部日志和页码，随后继续下一页。其他异常原样抛出，由现有外层错误处理负责。

返回值是发生 `1200` 的页码列表，便于日志和测试观察；当前业务调用方无需据此向用户
显示提示。

## 两条发送路径

### 手动“卡价图报”

将当前内联 `for` 循环替换为 `send_qq_pages` 调用。单页回调仍使用
`bot.send(event, MessageSegment.image(...))`。所有页面尝试完成后，继续发送原有的
“图报发送完毕”消息。这样 `1200` 不会到达外层异常处理，也不会弹出“生成失败”。

### 自动日报

每个管理员分别调用一次 `send_qq_pages`。某一页出现 `1200` 时，后续页面和后续管理员
仍会处理。全部 QQ 发送尝试结束后，继续记录发送日志并使用未压缩原图发布 B 站动态。

## 错误边界

- 只容忍数值型 `retcode == 1200`。OneBot V11 的返回字段位于异常的 `info` 映射中。
- 不根据错误文本模糊匹配，避免误吞其他超时或业务错误。
- 不容忍其他 `ActionFailed`、编码错误、连接错误或回调内部错误。
- 不改变图片压缩、页面顺序、B 站原图发布和成功提示。

## 测试

- 使用真实 OneBot V11 `ActionFailed` 发送三页，第一页返回 `1200`，确认三页都被尝试、
  无重试且返回第一页页码。
- 中间页返回非 `1200`，确认异常原样抛出且后续页不再发送。
- 源码契约确认手动和自动路径都通过统一发送函数，B 站仍使用原图。
- 运行 Cardrush 专项测试、全量测试、`compileall`、`pyflakes` 和插件加载验证。
